fix(ADR-032): persist tool_result_compression_mode across live-edit + restart

The Desktop "工具压缩" mode selector appeared to not stick across restarts.
Three coupled bugs in the live-edit pipeline were responsible:

1. cli.rs:1913 destructured the proto field into `_`, discarding it
   before constructing RuntimeConfigOverrides.
2. cli.rs:1954 hard-coded the field to None, so even a re-broadcast
   was a no-op for the in-memory cache.
3. The persistence block (cli.rs:2111-2130) had explicit assignments
   for 8 override fields but no branch for `tool_result_compression_mode`,
   so the on-disk file was never updated.
4. ConfigSnapshot (cli.rs:723) never returned the field, so the next
   GET from the Gateway → frontend would always see null → "auto".

Fix:
- Pass through `tool_result_compression_mode` from the destructured
  GatewayResponse to RuntimeConfigOverrides (cli.rs:1913/1950).
- Centralise the override → AgentConfig mapping in a new
  `RuntimeConfigOverrides::apply_to(&mut AgentConfig)` method
  (session_manager.rs), eliminating the copy-paste-driven schema-drift
  hazard that allowed bug #3 to slip in.
- Use `apply_to` in the cli.rs persistence step.
- Surface `tool_result_compression_mode` in ConfigSnapshot so the
  next GET round-trip sees the live-edited value.

Regression tests:
- 9 unit/integration tests cover the round-trip: push → apply_to →
  save → load → boot From<&AgentConfig>.

Refs: ADR-032 C4b
